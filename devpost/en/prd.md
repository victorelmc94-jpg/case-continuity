# Case Continuity — Product Requirements

## What We Are Building

A local review workspace to incorporate one new update into a fictional fiber/two-line advisory case, retaining sources, conditions, uncertainty and prior facts. Explicit human authority governs incorporation and review completion. Not a tariff recommender or contract processor.

## Core Journey

1. Open an independent trial and read saved case, state, sources and next action.
2. Enter a dated/attributed note. If present, provide separate document text with a different source reference.
3. Request analysis; inspect interpretation, concrete changes, prior values, exact citations and doubts. Analysis writes no case data/completed history.
4. Accept, edit or reject each card. No default bulk acceptance. Editing a proposal does not call the model.
5. Optionally save reviewed incorporations without declaring completion.
6. Resolve all visible cards, then explicitly confirm completion. Remaining approved effects and conclusion save together.
7. Reopen or restart and recover actual disk data rather than reconstructed conversation/model output.

## Screen and Presentation

One desktop-oriented screen: saved case, source/review workspace, proposals and confirmed history; stacked on narrow screens. Clear labels distinguish saved/proposed/pending. Plain commercial language, system fonts, keyboard focus and textual statuses. No additional administration or customer library.

History presents readable before/after, conditions, date and citations. JSON is secondary/collapsed. Preserve tentative wording equivalent to “could consider”; highlight the customer's explicit request not to contract with its source. Model interpretation is separate from V1's technical restriction.

## Case and Sources

Needs, declared fiber/mobile count, reference/conditional budget, offers, documentation, interest, operational state, next action, antecedents and uncertainties. Source date differs from review date. A statement is attributed, not verified; receiving a document does not validate authenticity.

In-scope fields remain writable for legitimate reviewed changes. New waits combine with unresolved work; newer dates do not resolve contradictions or tasks. Only supported resolution/cancellation/replacement permits removing an action. A proposed action is never marked performed.

Contract authorization is immutable in V1. The model must independently state explicitly absent, unestablished, uncertain or expressly reported authorization with citations. A blocked field cannot pass semantic evaluation.

## Proposals and Conditions

Typed proposals support fiber correction, allowed field updates, conditional budget, offers, document receipt, interest, uncertainty and antecedents. Corrections retain prior values in history/versions. Conditional willingness stays alongside the unconditional reference. A promised invoice is not received. Conflicting conditions retain both sources without automatically preferring recency.

Each card shows purpose, previous/proposed value, evidence, conditions and uncertainty. Schema validity is insufficient: assess original meaning before controls/correction. All material conditions must remain intelligible after saving. Empty structured interest conditions are an observed extraction limit even when declaration/citation preserve those limits; never treat that emptiness as unconditional acceptance.

## Review, Partial Save and Completion

All cards start pending. Accepted edits keep revised actual values and original quotations, without invented evidence. Only explicit accepted/accepted-edited changes save. Rejected/pending changes do not enter case data. Partial saving can create a data version but no completion event; reopening shows incorporated effects and unfinished review status.

Finish only on explicit confirmation after visible cards have decisions. A no-change review records “Reviewed, no changes”, sources, date and optional useful reason, retaining data version. Completion after partial incorporations acknowledges them rather than falsely claiming no changes. An approved antecedent is new information even if operational state is unchanged.

Unchanged repeated source/reason/effect does not duplicate history/versions. Different sources are not merged merely for similar text. Stale/conflicting saves are rejected, not silently rebased.

## Draft and Exit

Session-memory drafts without autosave. Changing source invalidates analysis; changing a proposal requires explicit acceptance. Internal navigation/reload shortcuts/browser exits warn where supported. Returning preserves the draft; discarding neither saves nor finishes. Browser restrictions/forced shutdown can prevent warnings. Saved data survive; drafts do not.

## Acceptance and Evidence

Six fictional families and positive controls distinguish conditional/unconditional budget, correction, actual/promised document, interest/no authorization, contradiction and no-change/repetition. Evaluate MODEL original meaning, GUARDS save enforcement and RECOVERY independently. Critical failures cannot be averaged away. Record original output/context and test actor.

The participant tested a novel source, accepted three cards, reread and identified a lost pending clarification. They did not test Edit or time savings. Preserve that original failure. Corrected generation and delegated Edit/reopen are agent evidence. Readiness and submission remain explicit participant decisions.

## Non-Goals and Later Work

No presentation-driven new features, real data, integrations, OCR, hosting, pricing search or transactions. Full review effort/corrections must be compared with a manual update before claiming savings; that has not been measured. Demonstrate meaningful persisted effects, not a generic AI summary.
