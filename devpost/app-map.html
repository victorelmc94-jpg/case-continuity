Case Continuity: from proposal to saved case

A local review tool for a fictional telecom case. The model proposes; an explicit reviewer command decides what is incorporated. Closing or analyzing does not finish review.

One action through the application

New update
app.js · analyze→Proposal only
model.mjs · analyze→Explicit approval
domain.mjs · commitReview→Atomic save and new read
store.mjs · transact

Saved data, receipts, sources, versions and review conclusion travel together. Unsaved draft decisions remain only in memory.

Three-stop reference route

This is a reference route, not a claim that the participant toured source code.

  1. public/app.js — find renderDraft and save. Editing changes the actual proposal value only after “accept this edit”; saving sends explicit decisions.
  2. src/domain.mjs — find commitReview. Pending/rejected proposals cannot become approved writes; a final review needs its explicit confirmation. Receipts preserve before/after and sources.
  3. src/store.mjs — find atomicWrite and WorkspaceStore.transact. Write a complete next workspace, then reread it. src/server.mjs returns that saved view when reopened.

To change this, start here

  • Proposal wording/interpretation rules: src/model.mjs · instructions; check originals before human edits.
  • What can be saved and how: src/domain.mjs · validateProposal / commitReview.
  • Readable history or no-contract wording: public/presentation.mjs and public/app.js · renderReceipt.
  • No-key replay packaging: scripts/prepare-demo.mjs; it never generates or resets usage.

A practice to reuse

The participant found a next action that lost an unresolved clarification even though saving/reopening worked. That showed why successful storage cannot prove correct interpretation. The approved requirement in devpost/prd.md · Propuestas con límites led to general pending-action instructions and three original-response contrasts. tests/release.test.mjs separately checks saved effects and retained literal conditions.

On another project, keep semantic quality, approval controls and persisted results as separate checks. Preserve the failing original instead of correcting the evidence after the fact. This is technical guidance, not a personal learning testimonial.
